## Context

Since ADR-026 the build has refused a published bundle over 2,000,000 bytes, the limit of paseo.cafe's
security scan. By the mission line the two entries were 34 bytes under it. Every change then had to
find bytes first, by shortening messages agents read or by moving data out of the bundle, before it
could be built. The limit belonged to a third party's listing, not to Paseo or to npm, which load and
publish larger plugins.

## Decision

1. **paseo-bm does not depend on paseo.cafe.** Releases go to npm through `release.yml`, and users
   install with `paseo plugin add npm:paseo-bm-plugin`. A release does not wait for, check or update
   a paseo.cafe entry, and paseo.cafe's scan rules are not requirements of the product or the build.
2. **The published bundle has no size limit.** The build, the packed smoke test and the package tests
   no longer refuse an entry set by its size, and nothing is trimmed to fit one. Size is still worth
   keeping reasonable, like any cost, but it never blocks a change.
3. **The published form stays as it is.** `plugin-package/` is still generated by `npm run build`,
   bundled one file per entry with identifiers minified and names kept (ADR-026, ADR-030), because it
   is one self-contained loadable plugin with no dependencies. Its other checks stay: built from
   `plugin/`, the exact file list, no install scripts, no dependencies, only host and Node imports.

## Consequences

- The test "stays within paseo.cafe's scan budget" and the build's size gate are removed, because
  their requirement is gone; no other test is weakened.
- A paseo.cafe entry, if it still exists, may fall behind the package. It is not maintained as part of a
  release; the listing record stays as history.
- Records written before this decision keep their paseo.cafe wording: accepted ADRs, release notes,
  dated acceptance records and the archive.
